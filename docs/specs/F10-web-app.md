## Goal
One React app with two data sources behind one interface:
- **Live**: talks to the local anvil fork through viem, sends real swaps from anvil's trader key, exactly like `demo.ts`. Used for the judging demo and the video.
- **Replay**: reads runs recorded from the live fork by the same engine (`web/public/runs/*.json`). Used by the public deployed site, where there is no chain.
Every number on screen comes from the fork, live or recorded. No number is typed into the UI.

## Engine (web/src/lib)
- viem **2.21.0** exact (same as scripts). `tsconfig.app.json` has `erasableSyntaxOnly`: no enums, no constructor parameter properties (`demo.ts`'s `Session` must be rewritten as a plain class or closure).
- Swaps: `PoolSwapTest.swap` with `hookData = abi.encode(uint256 hint)`, `amountSpecified = -amountIn`, price limits MIN+1 / MAX-1, **`gas: SWAP_GAS_LIMIT` (1,500,000) on every send and every simulation (D-20)**.
- Reads: the `readSnap` of `demo.ts` (balances, Aqua `rawBalances`, slot0 sqrtPrice and liquidity via `getStorageAt`, pools slot 6).
- Legs: parse `AquaFill` / `AquaSkipped` from the receipt; decode the reason with the same logic as `decodeSkipReason`. Never assume a fill.
- Price for display: `usdcPerMumb(sqrtPriceX96, usdcIsCurrency0)` with bigint maths, 6 decimals, rounded down. Price move uses `priceMovePercent` semantics (sqrtPrice squared, as `demo.ts`).
- All amounts stay `bigint`; JSON uses decimal strings. Format only in `format.ts`.

### Data source interface (the contract between T1 and T2; write it first)
```ts
interface DataSource {
  kind: "live" | "replay";
  header(): Promise<Header>;                       // pair, fee, sqrtPrice, usdcPerMumb, liquidity, bandBps, feeE9
  amounts(dir: Direction): string[] | "any";       // replay: recorded amounts only; live: "any"
  compare(req: { dir: Direction; amountIn: bigint }, onPoint?: (p: QuotePoint) => void): Promise<RunFile>;
  guard(amountIn: bigint): Promise<GuardFile>;
}
type RunFile = {
  schema: 1; fork: { block: number }; request: { dir: Direction; amountIn: string };
  quote: { points: { hint: string; out: string | null }[]; hint: string; aquaShare: number };
  poolOnly: RunJson; split: RunJson;               // RunJson = demo.ts RunRecord, bigints as strings,
};                                                 //   plus skipReason?: string (decoded), gasUsed
type GuardFile = {
  schema: 1; fork: { block: number }; amountIn: string; hint: string;
  move: { amountIn: string; out: string; sqrtBefore: string; sqrtAfter: string };
  hinted: RunJson & { skipReason: string };
};
```
No timestamps, tx hashes or snapshot ids in these files, so two records are byte-identical.

### Live source: snapshot discipline (coexists with the CLI)
- Connect: `web3_clientVersion` must start with `anvil`, the PoolManager must have code, and `deployment.trader` must equal the address of the key. Otherwise refuse live mode and show why.
- Deploy-state check: `readSnap()` must equal the `before` snap of the recorded 1,000 USDC run (balances and sqrtPrice; addresses come from the live deployment). If not, show a banner "Chain is not at the deploy state: run `pnpm --dir scripts run demo:reset`" with a "Continue anyway" button.
- Then `W = evm_snapshot`, held in memory only. Every action: `revert(W)` then `W = snapshot` before any swap; after the action, `revert(W)` and `W = snapshot` again, so the chain is always left at the deploy state, as the CLI does (D-23).
- Compare: revert/snap, read, quote (eth_call only), pool-only swap, read, revert/snap, read (assert equal to the first read), split swap with the quoter's hint, read, revert/snap.
- Guard: as `demo.ts guard`: quote first, pool-only move of `GUARD_MOVE_AMOUNT` (1,500 USDC), then the hinted swap with the pre-move hint, read the skip, revert/snap.
- If `evm_revert` returns false (a CLI command consumed our id: reverting to the CLI's older snapshot also drops ours), re-run the deploy-state check and take a new snapshot. Show it as a quiet toast, not an error.
- One action at a time: a busy lock disables every action button while one runs.
- Deployment: in `vite dev`, a 15-line Vite plugin serves `../deployments/local.json` at `/__local/deployment.json` (dev only). Live mode reads that. RPC: `?rpc=` query param, default `http://127.0.0.1:8545`.
- Trader key: `vite.config.ts` reads `TRADER_PRIVATE_KEY` from the root `.env`, falling back to `.env.example` (anvil's public key #2), and injects it with `define`. It is used only after the anvil check above.

### Replay source
- Loads `/runs/index.json` (list of files and amounts). Amount chips show recorded amounts only; the free input is hidden in replay.
- Header comes from the recorded `before` snap.
- Simulates the live pacing lightly (quote points appear over ~1 s) so the screen behaves the same in both modes.

### Record script
`pnpm --dir web run record` (node, `--env-file=../.env.example --env-file-if-exists=../.env`, tsx) runs the engine's live source against anvil and writes: `usdc-to-mumb-500.json`, `-1000.json`, `-2000.json`, `mumb-to-usdc-1000.json` (Tier 2), `guard-1000.json`, `index.json`. It leaves the chain at the deploy state.

### Visual style
- Theme tokens on `:root`; dark default, light theme toggle for washed-out projectors.
  - dark: bg `#0A0F1C`, surface `#121A2B`, line `#23304A`, text `#F2F5FA`, muted `#9AA7BD`
  - Aqua leg / Priya: teal `#2DD4BF`; pool leg: amber `#F59E0B`; CONFLUENCE result: text white with teal accent; refused: `#F87171`; ok: `#4ADE80`. Never colour alone: every colour also has a label.
- Type: Geist (UI) and Geist Mono (all numbers, `tabular-nums`), bundled with `@fontsource` (venue Wi-Fi). Hero numbers 56-64 px, body 18 px minimum.
- Motion (`motion` package, the only animation dependency): numbers count up once when a run lands (400 ms), the split streams draw left to right (600 ms), the guard marker slides out of the band. Respect `prefers-reduced-motion`. No idle animation.
- Tailwind v4. No component library.

## Acceptance
- Live, on a fresh `deploy`: "Run both" at 1,000 and 2,000 USDC shows the same MUMB out, average prices, price moves and gain as `pnpm --dir scripts run demo` (and `last-demo.json`). Guard shows `PoolPriceBandExceeded`, 3.14% against 2.00%, 949.918037701570887505 MUMB.
- Live and CLI coexist: web run, then `demo`, then web run again: both CLI outputs identical to the first, web recovers its snapshot without an error.
- `pnpm --dir web run record` twice: `git diff --exit-code web/public/runs` passes. `usdc-to-mumb-1000.json` `split.mumbOut` equals `last-demo.json`.
- `pnpm --dir web test` passes (format, price, decode, searchHint copy equals the scripts' on fixed fixtures). `pnpm --dir web build` passes with no type errors.
- Replay build served by `vite preview` with anvil stopped shows every screen with recorded numbers and the badge "REPLAY".
- Live mode refuses a non-anvil RPC with a visible reason.
- Deployed on Vercel (root `web`, build `pnpm build`, output `dist`); URL in README.
- Screenshot of the Swap screen after "Run both" at 1,000 USDC saved to `docs/demo-screenshot.png`.
